# Phase 3 Experiment Protocol & Methodology

This document outlines the experimental protocol, measurement methodologies, and performance evaluation criteria used for Phase 3 AODV multi-hop vehicular network testing.

---

## 1. Network Topology & Physical Configuration

- **Number of Nodes**: 5 Vehicle On-Board Units (`V1`, `V2`, `V3`, `V4`, `V5`)
- **Highway Alignment**: Straight linear alignment along longitudinal axis:
  - `V1`: $(100.0\text{ m}, 180.0\text{ m})$ — IP: `10.0.0.1`
  - `V2`: $(350.0\text{ m}, 180.0\text{ m})$ — IP: `10.0.0.2`
  - `V3`: $(600.0\text{ m}, 180.0\text{ m})$ — IP: `10.0.0.3`
  - `V4`: $(850.0\text{ m}, 180.0\text{ m})$ — IP: `10.0.0.4`
  - `V5`: $(1100.0\text{ m}, 180.0\text{ m})$ — IP: `10.0.0.5`
- **Inter-Vehicle Headway Distance**: $250.0\text{ m}$ between adjacent vehicles.
- **Total Highway Distance (V1 to V5)**: $1000.0\text{ m}$ ($1.0\text{ km}$).
- **Wireless Radio Range**: $R = 300.0\text{ m}$.
  - $d(V_i, V_{i+1}) = 250\text{ m} \le 300\text{ m}$ (Direct communication feasible).
  - $d(V_i, V_{i+2}) = 500\text{ m} > 300\text{ m}$ (Direct communication impossible).
  - $d(V_1, V_5) = 1000\text{ m} \gg 300\text{ m}$ (Multi-hop forwarding is mandatory).
- **Physical/MAC Layer Parameters**:
  - DSRC / IEEE 802.11p Bitrate: $6.0\text{ Mbps}$
  - Propagation Delay: $0.5\text{ ms}$
  - Payload Size: $256\text{ bytes}$ ($2048\text{ bits}$)
  - Serialization Delay: $t_{\text{tx}} = \frac{2048}{6 \times 10^6} \approx 0.3413\text{ ms}$
  - Single-Hop Data Latency: $t_{\text{hop}} = 0.3413 + 0.5000 = 0.8413\text{ ms}$

---

## 2. Performance Metrics Definition & Calculation

### 2.1 Packet Delivery Ratio (PDR)
Measures the percentage of transmitted application warning packets successfully delivered to the target vehicle:
$$\text{PDR} = \left(\frac{N_{\text{received}}}{N_{\text{generated}}}\right) \times 100\%$$

### 2.2 End-to-End Latency ($T_{\text{e2e}}$)
Elapsed wall-clock simulation time from the instant the application generates the warning packet at $V_1$ until it is completely received and parsed at $V_5$:
$$T_{\text{e2e}} = t_{\text{reception}} - t_{\text{generation}}$$
For the initial packet, $T_{\text{e2e}}$ includes the route discovery delay:
$$T_{\text{e2e, initial}} = T_{\text{discovery}} + T_{\text{data-forwarding}}$$

### 2.3 Route Discovery Time ($T_{\text{discovery}}$)
Elapsed time between $V_1$ broadcasting the `AodvRreq` message and receiving the unicast `AodvRrep` message from the destination:
$$T_{\text{discovery}} = t_{\text{RREP\_received}} - t_{\text{RREQ\_broadcast}}$$

### 2.4 Routing Overhead ($O_{\text{routing}}$)
Total count of control packets generated by the AODV routing engine:
$$O_{\text{routing}} = N_{\text{RREQ}} + N_{\text{RREP}} + N_{\text{RERR}}$$

## 3. Detailed Experiment Protocols

### Experiment 1: Initial Route Discovery
- **Objective**: Prove on-demand route discovery from an empty routing table.
- **Protocol**:
  1. Initialize all routing tables to empty.
  2. At $t = 15.0\text{ s}$, $V_1$ initiates a 256-byte `SUDDEN_BRAKING_WARNING` addressed to `10.0.0.5`.
  3. $V_1$ buffers the payload and broadcasts `AodvRreq` (ID=1).
  4. Trace the RREQ traversal: $V_1 \to V_2 \to V_3 \to V4 \to V5$.
  5. Trace the RREP traversal: $V_5 \to V_4 \to V_3 \to V_2 \to V_1$.
  6. Measure discovery latency, release buffered packet, and verify multi-hop data traversal.

### Experiment 2: Repeated Transmission & Route Cache Reuse
- **Objective**: Demonstrate that once a route is established, subsequent transmissions incur zero routing overhead and experience lower latency.
- **Protocol**:
  1. $V_1$ transmits 10 sequential warning packets at $1.0\text{ s}$ intervals ($t = 15.0\text{ s}, 16.0\text{ s}, \dots, 24.0\text{ s}$).
  2. Observe that Packet 1 triggers route discovery ($T_{\text{discovery}} = 4.49\text{ ms}$, $T_{\text{e2e}} = 7.86\text{ ms}$).
  3. Observe that Packets 2 through 10 use the cached active route entry without generating any RREQ/RREP packets, achieving pure transmission latency ($T_{\text{e2e}} = 3.37\text{ ms}$).

### Experiment 3: Intermediate Link Failure & Route Error (RERR)
- **Objective**: Validate link breakage detection, route table invalidation, and precursor notification via `AodvRerr`.
- **Protocol**:
  1. Establish active multi-hop route between $V_1$ and $V_5$.
  2. Transmit 5 packets successfully.
  3. At $t = 19.5\text{ s}$, simulate intermediate vehicle $V_3$ experiencing catastrophic hardware failure or driving out of communication range.
  4. At $t = 20.0\text{ s}$, $V_1$ sends the 6th packet.
  5. Upstream node $V_2$ detects link failure when forwarding to $V_3$.
  6. Verify that $V_2$ invalidates its route to $V_5$, increments destination sequence number, generates `AodvRerr`, and notifies precursor $V_1$.
  7. Verify that $V_1$ receives RERR and marks its route to $V_5$ as INVALID.

### Experiment 4: Route Rediscovery After Recovery
- **Objective**: Verify that upon route invalidation, fresh data transmissions trigger on-demand rediscovery, restoring communication once connectivity is re-established.
- **Protocol**:
  1. Following Experiment 3's link break, restore $V_3$ at $t = 19.5\text{ s}$.
  2. At $t = 20.0\text{ s}$, $V_1$ generates a new warning packet.
  3. Because the route was marked INVALID, $V_1$ initiates a new route discovery (`RREQ_2`).
  4. Verify that a fresh route is established, and subsequent packets are delivered.

### Experiment 5: Multi-Hop Collision Warning Application
- **Objective**: Demonstrate real-world vehicle telemetry dissemination matching Phase 1 SUMO parameters.
- **Protocol**:
  1. At $t = 15.0\text{ s}$, $V_1$ triggers sudden braking.
  2. Transmit 5 warning packets containing timestamp, speed ($13.3\text{ km/h}$), position ($x = 348.5\text{ m}$), and event code (`SUDDEN_BRAKING_WARNING`).
  3. Verify 100% delivery across 4 hops to $V_5$.

### Baseline Comparison: Direct Single-Hop Communication
- **Objective**: Benchmark AODV against non-routed single-hop transmission.
- **Protocol**:
  1. Disable multi-hop ad-hoc routing.
  2. $V_1$ attempts direct wireless transmission to $V_5$.
  3. Distance is $1000\text{ m}$; radio range is $300\text{ m}$.
  4. Measure PDR (0%) and document the necessity of multi-hop ad-hoc routing.
